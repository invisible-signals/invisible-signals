# Contributing to Invisible Signals™

Thanks for your interest in improving Invisible Signals™.

This project is opinionated. Contributions should make the system clearer, more useful, and more honest for engineers and leaders trying to communicate real experience.

## Good Contributions

Strong contributions usually do one or more of the following:

- Improve clarity, accuracy, or practical usefulness.
- Add examples grounded in realistic engineering or leadership scenarios.
- Strengthen the project's ethical boundaries.
- Fix mistakes, ambiguity, accessibility issues, or confusing wording.
- Improve tooling, structure, tests, or maintainability.

## Please Avoid

Please do not contribute material that:

- Encourages candidates to fabricate experience.
- Optimizes for deception, evasion, or interview manipulation.
- Copies proprietary interview questions or confidential company material.
- Adds generic career advice without connecting it to the Invisible Signals™ philosophy.
- Introduces unnecessary complexity or broad rewrites without a clear benefit.

## Pull Requests

Before opening a pull request:

1. Check whether an issue or discussion already covers the idea.
2. Keep the change focused.
3. Explain the purpose of the change and the user need it serves.
4. Include examples or tests when they help reviewers evaluate the change.
5. Confirm that your contribution can be licensed under Apache 2.0.

By submitting a contribution, you agree that it will be licensed under the Apache License 2.0 unless you clearly mark it otherwise before submission.

## Review Priorities

Maintainers will evaluate contributions for:

- Alignment with the project philosophy.
- Practical value to engineers and technical leaders.
- Accuracy and clarity.
- Respect for brand boundaries.
- Maintainability.

Not every useful idea belongs in this repository. A declined contribution is not a judgment on the contributor.
